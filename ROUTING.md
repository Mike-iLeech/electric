# Живые соединения и правила трассировки

## Принятые правила

- Выход из правого пина направлен вправо, вход в левый пин — слева. Свободный пин не имеет короткого наружного вывода.
- Только горизонтальные и вертикальные участки; дуги используются для обозначения пересечения без электрического контакта.
- Единый шаг параллельных дорожек — 12 мировых единиц. Масштаб меняет всё изображение согласованно.
- Линии одного источника и направления группируются в общий коридор. Длинная часть проходит пучком; веер у источника и ответвления у адресатов разнесены по порядку портов/расположению адресатов.
- Если близкому адресату недостаточно места для полосы пучка, его ветвь отделяется: маршрут не должен делать ненужный заход за адресата и возвращаться назад.
- Модули обходятся с зазором. Если готовый коридор занят, поиск учитывает длину, повороты и пересечения. Повороты и пересечения имеют отдельные штрафы; шаг дорожек остаётся одинаковым.
- Сортировка маршрутов детерминирована: создание тех же связей в другом порядке не меняет их геометрию.
- Нулевые отрезки и обратные коллинеарные хвосты сворачиваются. Пересечение провода с самим собой не превращается в дугу. Концы SVG имеют butt-окончание без выступающих колпачков.

Это конкретные правила автороутера приложения. Общий ориентир по оформлению электротехнических документов — [IEC 61082-1](https://webstore.iec.ch/en/publication/4469). Группирование соединений — также отдельная операция в [EPLAN](https://eplan.help/en-us/Infoportal/Content/Plattform/2.9/Content/htm/routinggui_h_autobuendeln.htm). Полное нормативное соответствие не заявляется; шаг 12 и стратегия общего коридора — принятые настройки редактора по требованию владельца, а не цитата из стандарта.

## Обновление при переносе

Провода больше не скрываются. Они представлены сохраняемыми SVG-объектами, отдельно от Canvas сетки и изображений капсул. За один requestAnimationFrame применяется последняя позиция указателя, выполняется скольжение по препятствиям и пересчитываются только затронутые маршруты:

1. Связи перемещаемого модуля/группы.
2. Связи, чей коридор перекрыт перемещённым модулем, перестраиваются с обходом новой позиции.
3. Представление дуг у участников изменившихся пересечений.

Остальные маршруты остаются теми же объектами с прежней геометрией. SVG-атрибуты обновляются только при реальном изменении пути/стиля. Фон и растровые капсулы при переносе не перерисовываются. При перемещении общего источника пучок строится как единое целое, без последовательного рассыпания на индивидуальные маршруты.

Если новая позиция не имеет допустимого маршрута в пределах бюджета поиска, редактор подходит к последней допустимой позиции, вместо исчезновения провода или рисования через модуль. Для очень плотных схем поиск ограничен: не заявляется нахождение глобального математического оптимума.

## Столкновения

Перемещение разложено по осям, препятствие ограничивает только нормальную составляющую. Касательная составляющая сохраняется — модуль скользит вдоль границы. Проверка охватывает весь пройденный участок, поэтому быстрый рывок не переносит карточку сквозь другую. Отступ между карточками — 16 мировых единиц; один перенос группы остаётся одним Undo.

## Проверки

80 тестов проходят, включая:

- Схему с длинными верхним/нижним пучками, похожую на предоставленный скриншот.
- Независимость от порядка создания связей.
- Перенос одного адресата и общего дистрибьютора.
- Перестроение перекрытых маршрутов при переносе неподключённого модуля через провода; остальные маршруты сохраняются.
- 20 шагов переноса с видимым SVG-проводом: меняется только связанный путь; счётчики перерисовки фона и капсул не растут.
- Скольжение при диагональном движении и запрет прохода сквозь карточку.
- Отсутствие выводов свободных портов и обратных хвостов.

Браузерный HTTP-предпросмотр дополнительно проверен реальным перетаскиванием дистрибьютора: все семь связанных проводов остались видимыми, сообщение об отсутствии маршрута не появилось. Продуктивный сайт не изменялся. Сборка: `node build.cjs` → `dist/index.html`.
